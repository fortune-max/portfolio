## What it is

Most chat assistants are good at talking about a task and stop there. I wanted one that would actually do it: plan the steps, call the services you've connected, write and run some code if that's the quickest way, and come back later to do it again on a schedule.

ThinClaw is that, for more than one person at a time. You send it a message, it shows you what it's doing as it goes, and you can stop it at any point. Each user gets their own workspace, their own encrypted credentials and their own choice of model. Integrations are plugins you switch on or off.

It's closed source for now, so this page is about how I think about it rather than how it's built. I'm happy to go through the details in an interview.

## How I think about safety

<AgentPrinciples />

Once an assistant can act, the interesting questions stop being about prompts. They're about whose data this is, what happens if the code it wrote loops forever, and who said it could send that email. These are the rules I hold it to:

- **Everyone's code runs in their own sandbox,** with limits per user. If isolation isn't available, the code doesn't run. There's no fallback that skips it.
- **Half a tool call is no tool call.** If the model sends something malformed or cut off, it's refused, never partly run.
- **Credentials are encrypted and kept out of the conversation.** The agent can use a key without seeing it, and logs are scrubbed.
- **Anything risky waits for a yes.** Sensitive or irreversible actions pause until the user approves them.
- **Scheduled jobs run once.** They survive restarts, never overlap, and fall back to another model provider if one is down or rate-limited.

## Where it's at

It's in private beta. So far that's about 38,000 lines of TypeScript, around 840 tests and 19 plugins, built since March 2026. Coding agents do much of the implementation; I own the design, the specs and every review.
