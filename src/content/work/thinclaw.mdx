## What it does

I message it like a person, by text or voice, and it acts across the services I've connected.

**It has its own computer.** Every user gets a private Linux environment with a full shell and their own storage, which stays between conversations. So it does the work instead of describing it: it can clone a GitHub repository and answer questions about the code, make a change to one of my projects while I'm out, write an article or a small web page and send me a link to it, or build a little browser game I can play from that link.

**It keeps track of ongoing work.** Longer things live in projects, each with its own brief, notes, files and history. I can pick one up from my phone days later, ask where it stands, and carry on.

**It learns my taste.** There's far more worth reading, watching and listening to than I'll ever have time for, so the hard part is choosing. ThinClaw learns from what I finish and how I rate it: about 2,600 books, films, shows, videos and podcasts so far. Each morning it goes through the newsletters I subscribe to and sends the three to five pieces most likely to be worth my time, each with a two-line summary and why it picked it. When I finish something, it asks what I thought, so the next picks get better.

**It handles the routine.** A short brief of the last day's email before I start work, and a weekly payment that goes out once I approve it in the chat. I set these up in plain words, like "every weekday at 8, summarise my email".

**It's useful in between.** I ask it how much I'd probably like a film or book I'm considering, based on how I've rated similar ones. I tell it things to remember and it files them in the right note, so "add oat milk" lands on the grocery list.

Some of the most useful moments are small. Send it a photo of a shopping cart and it tells you what it will come to at the till, by looking up every item in the supermarket's catalogue. It also tells me when my next bus is due, or whether the bike-share station near me has an e-bike free.

It's built for several people, each with their own plugins and choice of model.

## How I think about safety

<AgentPrinciples />

Once an assistant can act, the important questions stop being about prompts. They're about keeping each person's data and code apart, and making sure nothing irreversible happens without a yes. These are the rules I hold it to:

- **Everyone's code runs in their own sandbox,** with limits per user.
- **Plugin credentials stay with the plugin.** They go only to that plugin's code, never to the model or the shell, and once saved they can be replaced but never shown again.
- **Anything that moves money, deletes or overwrites, or reaches other people waits for a yes.** The pause is enforced in code, not in the prompt. For a payment, you approve the recipient as the bank has it, not the model's description of them.

## How it's built

I decide what to build and why, approve every design and every deploy, and use it daily to find what to improve. Coding agents turn our discussions into specs and plans, write the code and the tests, and a fresh agent reviews each branch before it merges. It runs on one small server for about $1–2 a month in model calls.
